1. У дереві цільового фрейма порахувати **значущі** вузли, які **не** є `INSTANCE` компонента (або еквівалент за вашими правилами).
2. У відповіді користувачу: **скільки** таких елементів (за бажання з групуванням).
3. Для кожного (або групи з однією причиною) — **рядок у [ui-components-backlog.md](ui-components-backlog.md)** (секція 2), обов’язково стовпець **«Чому в беклозі»** (наприклад: detached frame, немає COMPONENT у файлі, placeholder).
4. Якщо **0** — коротко повідомити; беклог не роздувати.

## Пастки (щоб екран не «обривався» і не ламався layout)

### `documentAccess: dynamic-page`

У частини файлів (у т.ч. **Moblie APP**) **`figma.getNodeById` недоступний синхронно** — помилка на кшталт *use figma.getNodeByIdAsync*. Для **COMPONENT** перед `createInstance()` завжди **`await figma.getNodeByIdAsync(id)`** у async-коді. Інакше скрипт падає **після** частини кроків (наприклад, уже є статус-бар і пошук, але немає картки візиту).

### Відповідь MCP після `figma_execute`

Не покладатися лише на `success: true`. Перевіряти поле **`result`** або явно зчитувати дерево дочірніх шарів цільового фрейма. Інакше можна не помітити **неповний** прогін.

### Auto-layout і `resize(..., мала висота)`

Не задавати батьківським **VERTICAL**-фреймам **`resize(width, 10)`** «для форми» — це фіксує мікроскопічну висоту і **стискає** контент.

### Hug висоти секцій (рекомендовано)

- Для **обгорток секцій** (шапка, рядок фільтрів, список, картки) краще **hug по висоті**, ніж довільний **fixed** (наприклад 900px на весь екран або фіксована висота «Filters»): у **VERTICAL** auto-layout це **`primaryAxisSizingMode: AUTO`**; у **HORIZONTAL** рядка висота йде через **`counterAxisSizingMode: AUTO`**.
- **Фіксовану висоту** лишають там, де вона **семантична**: статус-бар **~44px**, мінімальна зона тапу на чіпах/кнопках **~44px**, готові **INSTANCE** компонентів.
- **Пастка після переходу на hug:** якщо в **горизонтальному** рядку **`counter: AUTO`**, внутрішні фрейми-кнопки можуть стиснутися до висоти одного рядка тексту — додати **padding** батьку або **FIXED ~44** на фрейм кнопки, не повертаючи весь блок у штучний **fixed** без потреби.

### Відступ під fixed BottomNav у коді ≠ padding у Figma

- У коді (`pb-24`, **96px** тощо) відступ часто потрібен, бо **нижня навігація `fixed`** і перекриває скрол контенту — це **запас під бар** у зоні прокрутки.
- У макеті, якщо екран зібраний як **вертикальний стек** (контент **і** `BottomNav` **окремими** шарами зверху вниз, без накладання), той самий **96px** на фреймі списку дає **зайве «повітря»** між останнім елементом і навігацією.
- **Правило для цього репо:** у **stacked**-макеті **не** переносити **`pb-*` під навбар** на внутрішні фрейми контенту; додавати нижній padding лише якщо свідомо імітуєш **скрол у одному фреймі** з **фіксованим** баром поверх (рідко).

### Розбиття роботи

- Для інстансів компонентів за можливості **`figma_instantiate_component`** замість великого одного `figma_execute`.
- Великий скрипт + шрифти → ризик **timeout**; краще кілька коротких кроків або збільшений `timeout`.
- Після збірки — **чеклист секцій** екрану (імена/кількість дочірніх блоків) + **`figma_take_screenshot`** цільового фрейма; якщо скрін недоступний (**429** тощо) — структурна перевірка через **`figma_execute`** (див. skill **figma-canvas-verify**).

### Два проходи: структура і токени

- **Не змішувати** в одному довгому скрипті: (1) побудова фреймів/інстансів/тексту і (2) прив’язка до **Figma Variables** / стилів на кожному шарі — друге часто дає **тихі збої**.
- **Прохід A** — макет екрана (hug/fixed, stacked-навбар без зайвого `pb-*`).
- **Прохід B** (за потреби) — токени: skill **figma-bind-tokens**. У звіті вказати, якщо прохід B пропущено.

### Порядок операцій у `figma_execute`

- Спочатку **дерево** (`appendChild`), потім **`resize`** / детальні властивості auto layout.
- **`layoutMode`** задати **до** padding, alignment, sizing modes.
- Кольори в API часто як **RGB 0–1**.
- Текст у **INSTANCE** — через **component properties** / **`figma_set_instance_properties`**, не прямий редакт поверх інстанса.
