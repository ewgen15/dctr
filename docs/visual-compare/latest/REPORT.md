# Порівняння Home: код (Storybook) vs Figma

Джерела: `code.png` (Playwright), `design.png` (Figma MCP export), `diff.png` (pixelmatch). Метрика з `diff.txt`: **~7.06%** відмінних пікселів на канвасі **390×1005** (код був **390×844**, низ додано білим при вирівнюванні).

## 1. Глобальні відмінності

| Що | Спостереження | Рецепт |
|----|----------------|--------|
| **Висота скріну** | Код коротший за макет (~844 vs 1005 px): у знімку не весь вертикальний скрол або обрізано нижні блоки. | У `capture` збільшено початковий viewport для `--full-page`. Перезніми: `npm run visual:all -- ... --full-page`. Переконайся, що у Storybook story немає `overflow: hidden` на корені з фіксованою висотою меншою за контент. |
| **Шрифти** | Різний рендер (ClearType / Inter vs Figma). | Не «виправляти в пікселях»: звірити `font-family`, `font-weight`, `line-height`, `letter-spacing` у Tailwind/CSS з інспектором Figma. |
| **Тире в банері** | У макеті часто **en-dash** «–» у «пріоритет»; у коді може бути **дефіс** «-». | У рядку банера замінити на `\u2013` або символ `–`, якщо копірайт з Figma. |

## 2. Контент і дані (не помилка верстки, але дає diff)

| Зона | Відмінність | Рецепт |
|------|-------------|--------|
| **Аватар у картці візиту** | У коді — фото лікаря; у Figma — плейсхолдер з ініціалами «OR». | Узгодити з дизайном: або той самий asset/плейсхолдер у story, або прийняти різний контент для візуального тесту. |
| **Підзаголовок візиту** | Довший текст у коді («…кардіолога») vs коротший у макеті. | Вирівняти копі в `VisitCard` / моках story з Figma. |
| **Іконки сітки 2×2** | У макеті — умовні «ромби»; у коді можуть бути інші іконки (календар, відео тощо). | Підключити ті самі SVG/компоненти, що в Figma, або оновити макет під реальний набір іконок. |

## 3. Верстка та токени

| Зона | Ризик | Рецепт |
|------|--------|--------|
| **Відступи по горизонталі** | Різниця в `px` між секціями. | Звірити `px-5` / `gap` / `max-w` з padding frame у Figma (**~20px** з боків на 390). |
| **Кнопки «Деталі» / «Перенести»** | Ширина flex, border-radius. | У картці: однаковий `gap`, `min-h` для тач-таргету, `rounded-*` як у компонента в Figma. |
| **Нижня навігація** | Якщо на `code.png` обрізано — порівняння некоректне. | Спочатку відновити повну висоту скріну (п.1), потім звірити активний колір таба «Головна». |

## 4. Як повторити пайплайн з base64 MCP

```bash
npm run visual:decode-mcp -- --in path/to/figma-execute-response.json --out docs/visual-compare/latest/design.png
npm run visual:all -- --url "http://localhost:6007/iframe.html?id=pages-home--default" \
  --design docs/visual-compare/latest/design.png --out-dir docs/visual-compare/latest --full-page
```

Файл JSON має містити `result.base64` (типова відповідь `figma_execute` після `exportAsync`).

## 5. Висновок

Більшість **7%** піксельної різниці пояснюється комбінацією: **різна висота знімка коду**, **різний контент** (аватар, текст, іконки), **антіаліасинг шрифтів** і дрібні відмінності тире/копі. Після вирівнювання висоти (`--full-page` + кореневий scroll у story) і узгодження копі/плейсхолдерів має сенс перезапустити `visual:diff` і знову подивитися `diff.png`.
