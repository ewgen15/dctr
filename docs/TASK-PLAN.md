## Порядок роботи (логіка флоу)

1. Сценарій і точка входу з головної («Замовити ліки в аптеці поряд»).
2. Екран вибору: діючі речовини та препарати.
3. Редагування препаратів і кількості (кнопка редагування).
4. Карта аптек + пошук по адресі.
5. Фільтри на карті: ціна, відстань; слайдер діапазону цін.
6. Логіка відображення: лише аптеки з повною наявністю всіх позицій.
7. Розгорнутий картка аптеки: назва, адреса, ціна, бронювання.
8. Чекаут: товари, аптека, контакти клієнта з додатку.

## Чеклист

- [x] Сценарій бронювання ліків з деталей візиту (**Забронювати** → шит; окремий екран входу на старті не робили — як на мітингу).
- [x] У шиті: перелік призначених препаратів, варіанти/альтернативи (bottom sheet), під препаратом — діюча речовина після вибору (демо-дані).
- [x] Редагування: зміна варіанту препарата в шиті; кількість упаковок на `/checkout` (±). Повна узгодженість формату з Тарасом — окремо.
- [x] Карта аптек у шиті (`PharmacyMapDrawer`) + перемикач список/карта.
- [ ] Пошук по адресі та поведінка як у Booking (пошук + фільтрація).
- [ ] На карті: фільтри за **ціною** та **відстанню**; за замовчуванням відстань — «неважливо».
- [ ] Слайдер діапазону цін (мін → макс).
- [ ] На мапі лише аптеки з повною наявністю всіх позицій (зараз демо-маркери без цієї логіки).
- [x] Картка аптеки під картою: назва, адреса, ціна, **Замовити** → чекаут.
- [x] Чекаут `/checkout`: товари, аптека, оплата (демо), бронь.
- [ ] Контактні дані клієнта з профілю на чекауті (потрібен `/profile` та зв’язка).

## Storybook — покриття екранів

Усі роути з `src/app/routes.ts` мають сторінкові stories (`src/app/pages/*.stories.tsx`) для візуальної перевірки та зв’язку з Figma (`parameters.design`, де задано):

| Роут | Сторінка | Storybook | Figma (addon Design) |
|------|-----------|-------------|----------------------|
| `/` | `Home` | `Pages/Home` | `143-1016` |
| `/doctors` | `DoctorList` | `Pages/DoctorList` | `145-1105` |
| `/doctors/:id` | `DoctorProfile` | `Pages/DoctorProfile` | `146-1748` |
| `/visits` | `MyVisits` | `Pages/MyVisits` | окремий фрейм — за потреби |
| `/visit/:id` | `VisitDetails` | `Pages/VisitDetails` | `146-1916` |
| `/checkout` | `Checkout` | `Pages/Checkout` | немає — додати при синхронізації флоу аптек |

Журнал екранів і кандидати на компоненти: [docs/ui-components-backlog.md](./ui-components-backlog.md).
